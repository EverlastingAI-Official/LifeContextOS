# 理论与工程基础

## 1. 两套概念如何连接

“意识上传第一范式”给出三个对工程最重要的命题：

1. 语言是意识向外界发挥功能的基本媒介；这里的语言不限于文字，也包括具有沟通功能的声音、动作和其他符号。
2. 上传成功的根本哲学问题是主体连续性，而不只是生成内容是否相像。
3. L1 通过个体私有语言数据和个性化语言模型，先实现可测试的表达与行为模拟。

“人生上下文”则提供 L1 所需要的数据工程基础：

- 意识 token 是可记录的表达迹象；
- ThoughtCell 把表达变成带时间、场景、意图和关系的语义单元；
- LifeContext 将这些单元组织为生命时间序列与关系网络；
- Mindcopy 把较稳定的人格、价值、记忆和表达规则压缩成可运行配置。

因此，人生上下文不是意识上传完成后的附件，而是 L1 的数据基础设施；Mindcopy 也不是人生上下文本身，而是从人生上下文派生出的、可版本化的运行模型。

## 2. 项目的操作性定义

为了把哲学命题转成可验证的软件，本项目区分四类对象：

| 层级 | 回答的问题 | 是否可由模型修改 |
| --- | --- | --- |
| Evidence | 实际发生或记录了什么？ | 不可覆盖，只能追加版本和校正记录 |
| Semantic | 这段证据表达了什么？ | 可以重新计算，必须标明模型与置信度 |
| Identity | 哪些模式可被认为相对稳定？ | 需要本人确认并版本化 |
| Runtime | 此刻应该调用什么并做什么？ | 可以运行，但受权限与审计约束 |

## 3. L1 的验证目标

L1 不使用一个笼统的“意识相似度”，而使用可解释的分项指标：

- `identity_consistency`：基本身份事实是否正确；
- `episodic_recall`：对个人事件的召回是否准确且有出处；
- `value_alignment`：价值选择与本人历史判断的一致程度；
- `style_similarity`：措辞、节奏、语气和修辞的相似程度；
- `decision_similarity`：在保留测试集情境中的选择一致性；
- `uncertainty_calibration`：不知道时是否承认不知道；
- `temporal_fidelity`：是否避免用后来的认知污染过去的自己；
- `provenance_coverage`：重要回答有多少能追溯到证据。

评测集应由本人和可信见证人共同建立，并保留一部分从未进入索引或训练流程的盲测题。

## 4. 连续性的谨慎表达

项目将连续性拆成三个层次：

1. `narrative_continuity`：数字代理能否连贯讲述个人生命故事；
2. `behavioral_continuity`：数字代理能否在新情境中保持相似判断和表达；
3. `subjective_continuity`：第一人称体验是否真正延续或迁移。

前两者可被 L1 工程测量；第三者目前是开放的哲学与科学问题。产品界面、文档和营销均应保持这一差异。

## 5. 必须保留的反事实能力

可信的人生上下文系统不仅要“连接 dots”，也要能说：

- 这条关系只是模型推断；
- 存在相反证据；
- 当前资料不足以判断因果；
- 这个回答代表某一人生阶段，而非此人一生不变的观点。

没有这些能力，上下文图谱会退化成一台制造合理故事的机器。
